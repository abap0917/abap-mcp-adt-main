🐛 Bug Fix: xmlPatch.ts::patchXmlBlock silent-drop fix

Symptom. Even when fixed_values is passed to CreateDomain, the fixed values are empty in SE11. The update step silently drops without failing.

Root cause. fr0ster's patchXmlBlock replaces the target tag if it exists in the XML, but when it doesn't exist, xml.replace returns a no-op → injection fails when a newly created skeleton domain has no <doma:fixValues> tag at all.

❌ Before (v3.13.0 upstream)
function patchXmlBlock(xml, tag, content) { const regex = new RegExp( `<${tag}[\\s\\S]*?</${tag}>|<${tag}\\s*/>` ); return xml.replace(regex, content); // ↑ returns the original on match failure = silent drop }
✅ After (@babamba2 fork)
function patchXmlBlock(xml, tag, content) { const regex = new RegExp( `<${tag}[\\s\\S]*?</${tag}>|<${tag}\\s*/>` ); if (regex.test(xml)) return xml.replace(regex, content); // insert before the root closing tag when the tag is absent const root = xml.match(/<\/[a-zA-Z0-9:_-]+>\s*$/); if (!root) return `${xml}\n${content}`; return xml.slice(0, root.index) + content + '\n' + xml.slice(root.index); }
